# Bloom 内测安装说明

适用版本：`0.2.x`。development、preview、production 使用不同包名，可以同时安装，互不覆盖。

| 构建 | 显示名 | 包名后缀 | JS 来源 | 用途 |
|---|---|---|---|---|
| development | Bloom 开发 | `.dev` | 运行时连接 Metro | 开发调试、组件陈列、时间旅行 |
| preview | Bloom 内测 | `.preview` | 构建时内嵌 | 内部安装与验收 |
| production / TestFlight | Bloom | （无） | 构建时内嵌 | TestFlight 与正式发布前验证 |

## development 与 preview 的区别

- **development 是开发客户端。** 打开后先进入开发客户端连接界面（launcher），再连接电脑上的 Metro。电脑未启动 Metro、手机连不到电脑，或二维码地址不可达时，业务界面不会启动。
- **preview 是独立安装包。** JS 已打进安装包，不依赖 Metro，适合交给测试人员。TestFlight 包同样内嵌 JS，不要求测试人员连接开发电脑。
- `eas.json` 中 development 使用 `developmentClient: true`；preview 使用 internal distribution。两者不要混用。

## 构建命令

需已登录 EAS（`npx eas-cli@latest login`），并配置好 Apple / Google 凭证。

```bash
# 开发客户端（内部安装）
npx eas-cli@latest build --platform all --profile development

# preview 内测包：iOS 内部分发，Android APK
npx eas-cli@latest build --platform all --profile preview

# iOS App Store 构建，可提交到 TestFlight
npx eas-cli@latest build --platform ios --profile production
npx eas-cli@latest submit --platform ios --profile production
```

本项目使用 Continuous Native Generation。不要手工维护 `ios/`、`android/`，也不要为了内测安装手工执行 Gradle 或 Xcode 构建；原生配置写在 `app.config.ts` 和 config plugin 中。

## 使用 development 客户端

先安装 development 构建，再在项目目录启动 Metro：

```bash
npx expo start --dev-client
```

### iPhone 连接排查

1. **先用 LAN。** Mac 与 iPhone 连接同一局域网，关闭会隔离设备的访客 Wi-Fi；允许防火墙放行 Node/Expo。Metro 默认使用 LAN 地址。打开「Bloom 开发」，在 launcher 中选择发现的开发服务器，或用系统相机扫描终端二维码。
2. **LAN 不通时用 tunnel。**
   ```bash
   npx expo start --dev-client --tunnel
   ```
   tunnel 需要电脑与手机都能联网，速度通常慢于 LAN，并依赖 ngrok 服务。若 tunnel 本身报连接超时，先检查网络和 ngrok 服务状态。
3. **确认安装的是 development。** 「Bloom 内测」preview 不会显示 launcher，也不会连接 Metro。
4. **iOS 16 及以上开启 Developer Mode。** 安装 development 或其他 internal distribution 构建后，前往「设置 → 隐私与安全性 → 开发者模式」，按系统提示重启并确认开启。TestFlight 不需要 Developer Mode。
5. **launcher 找不到服务器时**，保持 Metro 运行，重新扫描二维码；仍不通则切换 LAN/tunnel，并确认二维码中的地址可从手机访问。

## iOS 安装与 UDID

### development / preview 内部分发

EAS 的 iOS internal distribution 使用 Ad Hoc 描述文件。设备 UDID 必须在构建所用的描述文件中：

```bash
# 注册新设备
npx eas-cli@latest device:create

# 查看已登记设备
npx eas-cli@latest device:list
```

- 新增设备后，旧安装包不会自动获得该设备权限。需要重新执行 development/preview 构建，或使用 `eas build:resign` 以包含新设备的描述文件重新签名。
- 如果设备已登记但仍提示无法安装，检查该设备是否出现在本次构建的 provisioning profile 中。非交互构建可能复用未包含新设备的旧 profile。
- 新开通或刚续费的 Apple Developer Program 账号中，新设备在 Apple 侧可能需要一段处理时间；设备尚未进入可用描述文件时，重新构建也可能失败。
- Ad Hoc 每个设备类型每个会员年度最多登记 100 台。卸载 App 会清空其本地数据，覆盖安装同包名且同签名版本会保留数据。

### TestFlight

TestFlight 使用 App Store 构建，不依赖 UDID，也不需要 Metro 或 Developer Mode。当前 `preview` profile 是 internal distribution，不是 TestFlight profile；要进入 TestFlight，应构建并提交 iOS `production` profile。

## Android 安装

1. 使用 preview profile 构建后下载 APK。
2. 手机设置中允许来源应用安装未知应用（各品牌路径略有不同）。
3. 用文件管理器打开 APK 安装。
4. 鸿蒙 NEXT（纯血鸿蒙）无法安装 APK。

## 验收清单

- [x] 打开 App 可见五个页签：今日 / 项目 / 统计 / 成就 / 我的
- [x] 「我的」→「关于 Bloom」可导出诊断日志（内容无项目名、心情）
- [x] development：「组件陈列」「时间旅行」可用；开启时间旅行后顶部有柠檬色提示条
- [x] preview 在没有 Metro 的情况下可以启动
- [x] 覆盖安装同签名新版本后，数据库测试数据仍在

## 签名与密钥保管

- iOS：证书与描述文件由 EAS 托管时可在苹果后台撤销重签；本地导出的 `.p12` 需双份备份。
- Android：`.jks` / `.keystore` 与密码双份备份；丢失只能换包名或卸载重装。
