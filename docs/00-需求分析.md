## 1. 产品定位

**一句话**：Bloom 是一个只装在自己手机里的习惯打卡手账。每坚持一天，日历上就开一朵小花。

| 项 | 内容 |
|---|---|
| 用户 | 内部使用的同事和朋友，以年轻女生为主，同时在坚持 2–6 件小事（早睡、喝水、背单词、运动、护肤……） |
| 核心任务 | 每天花几秒钟打完卡，并且能看到自己在一点点进步 |
| 情绪目标 | 打卡时有小确幸（花开了），回看时有成就感（花园满了），断了也不被责备（欢迎回来） |
| 不是什么 | 不是社交打卡、不是待办清单、不是健康数据平台。没有账号、没有服务器、不联网 |

### 1.1 成功怎么判断

内部使用不做埋点（数据不出手机），所以成功标准用"能实测的行为"和"内测反馈"来定义：

| 维度 | 标准 | 验证方式 |
|---|---|---|
| 打卡快 | 打开 App 到完成一次打卡 ≤ 3 秒；点击到动画开始 ≤ 50ms | 测试机实测 |
| 不丢数据 | 内测期 0 起数据丢失；导出→导入往返后所有数据逐条一致 | 回归用例 + 往返校验脚本 |
| 提醒准 | 按引导设置后台权限的机型，提醒在设定时间 ±1 分钟内到达 | 主流机型连续 7 天实测 |
| 愿意用 | 内测 2 周后 ≥ 70% 的人仍每天打卡；"好看、想打开"自评 ≥ 4/5 | 内测问卷 |
| 一致好看 | 每期视觉走查清单全部通过（见 `02-设计规范.md` 第 12 节） | 截图评审 |

## 3. 逐条需求理解

### 3.1 创建项目
- **打卡频率**：你列的"时间规划"和"打卡次数"本质是同一件事的两个维度（哪些天打 + 每天打几次）。我把它统一成 **7 种频率**，见 5.1。你提到的"每周""每月"理解为"每周任选 1 天""每月任选 1 天"。
- **起始日期**【假设】：你写的"起始日期（支持永远、1年、1月、3月等快捷日期）"，我理解为两件事：**开始日期**（默认今天，可选过去或未来）+ **坚持多久**（一直坚持 / 7 天 / 21 天 / 1 个月 / 3 个月 / 半年 / 1 年 / 自定截止日期）。"永远/1年/1月"是坚持多久的快捷选项。
- **提醒**：每个项目最多 5 个提醒时间，只在计划日提醒。
- **图标**：从内置 SVG 贴纸图标里选（106 个，8 个分类，可搜索），另选一个卡片颜色（12 种糖果色）。
- **记录成绩（备注）**：项目级开关。打开后，每次打卡完成会弹出一个可跳过的小面板写一句话（≤ 200 字）。备注事后可在记录里改。
- 补充：名称（必填，≤ 20 字）、鼓励语（≤ 40 字，可"换一句"）、计数单位（次/杯/页/组/个/遍或自定义 2 字，默认"次"）。

### 3.2 打卡
- 支持全部 7 种频率的打卡与进度计算。
- **补卡**：在日历上选中过去的日期直接打卡，和当天打卡的交互完全一样，不弹任何提示、不限次数。唯一限制是不能早于项目开始日期。
- 补充：撤销、防误触、多次打卡的分段进度、未来日期不可打卡，见 5.5。

### 3.3 日历 + 项目列表
- 首页 = 月历（可折叠为周）+ 选中日期的项目列表。
- 每个日期格显示当天整体完成情况（花朵三态）；列表显示选中日期每个项目的完成情况，可直接打卡/补卡。

### 3.4 历史记录
- 展示所有打卡记录：项目、归属日期、实际打卡时间、备注、心情标记。按月 → 按日分组，可按项目筛选，可删除和编辑备注。

### 3.5 我的项目
- 展示全部项目和完成情况；暂停/继续、编辑、删除、项目统计、项目历史。
- 补充：提前毕业、拖拽排序、分组。

### 3.6 统计
- 全部项目统计（总览）、按月、按年；单个项目统计在项目详情里。口径见 5.9。

### 3.7 心情记录
- 完成某天的某个项目、或某天的全部项目后可以记心情：心情表情（可选）+ 文字（≤ 500 字）+ 图片（≤ 5 张）。
- 入口做小：只是完成后卡片上的一个小图标、当日标题旁的一个小图标、长按菜单里的一项。不做底部大按钮，不做强制弹窗。

### 3.8 成就
- 内置 72 枚徽章，12 个系列，解锁节奏覆盖前 3 个月（见 `附录A-成就清单.md`）。
- 解锁后主动弹窗；徽章用 SVG 绘制，弹窗和详情中带动画。

### 3.9 自动结束
- 设置了截止日期的项目，截止日期过完后自动"毕业"，下次打开 App 播放毕业典礼（含证书），之后可以进入"回顾"看这段时间的全部记录。

### 3.10 导出导入
- 全部数据（项目、规则、记录、心情、照片、徽章、偏好）导出为一个 `.bloom` 备份文件，可在另一台手机（iOS ↔ Android 均可）导入恢复。另可导出 CSV 表格方便在电脑上看。不联网、不上传。

### 3.11 桌面小组件
- iOS：小/中/大号、锁屏组件、单项目组件，iOS 17+ 可在组件上直接打卡。
- Android：2×2、4×2、4×4、单项目组件，可直接打卡。

### 3.12 卡通少女风格
- 设计方向"花园手账"：奶油点阵纸底、糖果色块、可可色墨线、小兔吉祥物"朵朵"、花朵作为贯穿全局的符号。详见 `02-设计规范.md`。

## 5. 核心业务规则

研发、测试、设计都以本节为准。代码中的规则实现需与本节编号对应（例如注释写"口径见需求 5.9"）。

### 5.1 打卡频率（7 种）

| 频率 | 用户看到的写法 | 配置项 | 当天目标 | 周期目标 | 哪些天出现在列表 | 怎样算完成 |
|---|---|---|---|---|---|---|
| 每天 | 每天，每天 N 次 | N：1–20 | N | — | 每天 | 当天次数 ≥ N |
| 每周固定几天 | 每周一、三、五，每天 N 次 | 周几（至少 1 个）+ N | N | — | 选中的周几 | 当天次数 ≥ N |
| 每周任选几天 | 每周任选 X 天，每天 N 次 | X：1–7 + N | N | X 天 | 每天 | 周内完成天数 ≥ X |
| 每周累计次数 | 每周累计 X 次 | X：1–99 | 不限 | X 次 | 每天 | 周内次数 ≥ X |
| 每月固定几号 | 每月 1 号、15 号，每天 N 次 | 日期（至少 1 个）+ N | N | — | 选中的日期 | 当天次数 ≥ N |
| 每月任选几天 | 每月任选 X 天，每天 N 次 | X：1–31 + N | N | X 天 | 每天 | 月内完成天数 ≥ X |
| 每月累计次数 | 每月累计 X 次 | X：1–200 | 不限 | X 次 | 每天 | 月内次数 ≥ X |

补充规则：
- **月末不存在的日期**：选了 29/30/31 号，在没有这一天的月份改为当月最后一天；同月多个选中日落在同一天时只算一次。选到这几个日期时面板下方显示一行说明。
- **周期不完整**（项目在周期中间开始/结束/暂停）：任选几天类，目标 = min(目标天数, 该周期内有效天数)；累计次数类，目标 = 向上取整(目标次数 × 有效天数 ÷ 周期天数)。
- **周期型项目达标后**：仍出现在列表，显示"本周已达标"，仍可继续打卡（多出来的也计入记录和累计）。
- **累计次数类**每天最多记 99 次，防止误操作。
- **非计划日**【假设】：固定周几/几号的项目，在非计划日不出现、不能打卡。理由：保证"完成率"和"连续"口径简单可信。若内测反馈需要"额外打卡"，再加。

### 5.2 "一天"怎么算

- 默认 0 点为一天的分界。偏好设置可改为 1–4 点（夜猫子模式）：例如设为 2 点，凌晨 1:30 的打卡算前一天。
- 全 App 所有"今天"的判断（列表、统计、提醒、小组件翻日）都使用同一个"逻辑今天"。
- 记录同时保存"归属日期"和"实际打卡时间"，二者独立。

### 5.3 项目状态

| 状态 | 怎么进入 | 怎么离开 | 今日列表 | 允许 | 不允许 |
|---|---|---|---|---|---|
| 未开始 | 新建时开始日期在未来 | 开始日期到达后自动变为进行中 | 不出现；在日历上选中未来计划日时以"预览"出现 | 编辑、删除 | 打卡、暂停、毕业 |
| 进行中 | 开始日期到达；从暂停继续 | 暂停；毕业；删除 | 计划日出现 | 打卡、补卡、撤销、编辑、暂停、提前毕业、删除 | — |
| 已暂停 | 用户暂停 | 继续 → 进行中；截止日期到 → 已毕业；删除 | 暂停期间的日期不出现，暂停前的日期照常出现 | 补暂停前的卡、编辑、继续、提前毕业、删除 | 暂停期间的日期打卡 |
| 已毕业 | 截止日期过完自动毕业；或提前毕业 | 不能回到进行中（可"再来一轮"新建一个）；删除 | 起止范围内的过去日期照常出现（可补卡），之后不出现 | 补范围内的卡、撤销、看回顾、再来一轮、改名称/图标/颜色/鼓励语、删除 | 改频率和日期、暂停 |

没有死状态：每个状态都能删除；暂停可继续；毕业可再来一轮。

### 5.4 某天显示哪些项目、能不能打卡

对项目 P 和日期 D，按顺序判断，任一条命中即"不出现"：
1. D 早于开始日期；
2. 有截止日期且 D 晚于截止日期；
3. 已毕业且 D 晚于毕业日期；
4. D 在暂停区间内；
5. 按 D 当天生效的频率，D 不是计划日（只对"固定几天/固定几号"生效）。

出现的项目能否打卡：
- D 晚于今天 → 不能（点击时按钮轻摇，提示"还没到这一天哦"）；
- 当天次数已达目标（按天计数的频率）→ 不能再加，点击打开"已完成"小菜单；
- 其余都能。

### 5.5 打卡、撤销、补卡

- 点一次 = 一条记录，记下归属日期（选中的日期）和实际打卡时间（此刻）。
- **补卡**就是选中过去的日期打卡，不提示、不区分。历史记录里，若归属日期与实际时间不在同一天，时间显示为"11月19日 07:56"，否则只显示"07:56"。
- **撤销**：打卡后底部出现 3 秒的"撤销"条；之后也可以点已完成的花，选"撤销一次"，删除该项目当天最近的一条记录（附带的备注一起删除，心情不删）。
- **多次打卡**：按钮外圈分段，每点一次亮一段；最后一段亮起时花开。
- **防误触**：同一按钮 0.25 秒内的第二次点击忽略。
- 撤销不会收回已获得的徽章【假设】。

### 5.6 修改项目

| 改什么 | 规则 |
|---|---|
| 名称、图标、颜色、鼓励语、单位、提醒、成绩开关 | 随时可改，立即生效，包括历史显示 |
| 打卡频率 | 从今天起按新频率计算；今天之前按旧频率，历史统计不变。周期型从今天所在的周/月开始用新规则。保存前在频率行下方显示"从今天起按新频率计算" |
| 开始日期 | 可改得更早；不能晚于最早一条记录的日期（提示"最早的记录在 11月18日"） |
| 坚持多久 | 新的截止日期不能早于今天；改成"一直坚持"随时可以 |
| 已毕业项目 | 只能改名称、图标、颜色、鼓励语 |

### 5.7 暂停与继续

- 暂停从今天开始；今天如果已经打过卡，则从明天开始（今天照常算）。
- 继续：从今天恢复。暂停当天又继续，等于没暂停过。
- 暂停期间：不出现在列表、不提醒、不能打卡；统计时这些天不算"应打卡的日子"，不打断连续。
- 暂停/继续都是可逆操作，不弹确认，给 3 秒撤销条。

### 5.8 毕业

- **自动毕业**：截止日期那天过完（逻辑今天 > 截止日期），项目自动毕业。下次打开 App 时播放毕业典礼，每个项目只播一次；多个项目同时毕业时依次播放。
- **提前毕业**：项目详情"更多"里，二次确认后毕业，毕业日期 = 今天（今天仍在范围内）。
- 毕业后：之后的日期不再出现；范围内的日期仍可补卡和撤销，统计与证书数据随之更新。
- **再来一轮**：用原项目的设置新建一个项目（开始日期今天，时长与原来相同），原项目保留并互相关联。
- 证书评语按完成率分三档（≥ 90%、60%–89%、< 60%），任何完成率都是"毕业"，只是评语不同，见 `附录C-文案库.md`。

### 5.9 统计口径

| 指标 | 定义 |
|---|---|
| 计划日 | 按 5.4 该项目在这天"出现"的日子 |
| 完成日 | 当天次数 ≥ 当天目标次数；累计次数类当天 ≥ 1 次即算 |
| 本月完成 | 本月完成日的数量（累计次数类显示本月次数） |
| 累计完成 | 按天计数的显示"累计 X 天"，累计次数类显示"累计 X 次" |
| 当前连续 | 按天计数的：从今天（今天已完成时）或昨天往前数，连续完成的计划日数，跳过非计划日和暂停日。**今天还没完成不会让连续变成 0**。周期型：连续达标的周/月数，单位显示"周"/"月" |
| 最长连续 | 历史上出现过的最大连续值 |
| 完成率 | 按天计数的：完成的计划日 ÷ 已到来的计划日（今天只有完成了才算进分母）。周期型：达标周期 ÷ 已结束周期（当前周期达标了才算进分母） |
| 记录天数 | 至少有一条打卡记录的日子数（全部项目合并） |
| 累计打卡 | 打卡记录总条数 |
| 完美日 | 当天"必须打卡"的项目（每天、固定周几、固定几号三类）全部完成，且至少有 1 个；弹性项目（任选几天、累计次数）当天打了就一起算，没打不扣分 |
| 热力分级 | 当天完成项目数 ÷ 当天计划项目数：0、≤ 1/3、≤ 2/3、< 1、= 1（完美日）五级 |

### 5.10 提醒

- 每个项目最多 5 个提醒时间；只在计划日提醒；暂停、未开始、已毕业的项目不提醒。
- 两个开关（默认都开）：当天已完成就不再提醒；周期已达标就不再提醒（只对周期型显示）。
- 晚间汇总提醒（默认关，默认 21:30）：只在当天还有没完成的项目时提醒，内容列出没完成的项目名。
- 通知权限在用户第一次添加提醒时才申请，不在启动时申请。
- 通知内容："该去做「八段锦」啦" + 鼓励语。点击通知打开今日页并定位到该项目。

### 5.11 心情

- 两种：**项目心情**（某天某个项目完成后）、**当天心情**（某天全部项目完成后）。每个"日期 + 项目"组合最多一篇，每天最多一篇当天心情；再次进入即编辑。
- 内容：心情表情 5 选 1（可不选）、文字 ≤ 500 字、图片 ≤ 5 张；至少有一项才能保存。
- 打卡撤销后心情保留；项目删除后心情保留，显示"来自已删除的项目"。
- 未完成时不显示入口【假设】，与原需求一致。

### 5.12 成就

- 72 枚，12 个系列，4 个等级（花苞、小花、繁花、彩虹花），其中 6 枚隐藏。清单见 `附录A-成就清单.md`。
- 只增不减：撤销、删除记录、删除项目都不收回已获得的徽章。
- 判定基于"历史最大值"，补卡同样可以解锁。
- 同时解锁多枚时排队依次弹出；≥ 3 枚时提供"一次收下"。
- 老数据补发和导入后补发：合并成一张"补发"卡片，不逐个弹窗。

### 5.13 删除

| 删除什么 | 确认方式 | 连带影响 | 能否撤销 |
|---|---|---|---|
| 单条记录 | 不确认（左滑删除） | 备注一起删 | 5 秒撤销条 |
| 项目 | 确认框，写明"会同时删除 N 条打卡记录，心情会保留" | 记录、提醒、规则删除；心情保留；徽章保留 | 5 秒撤销条 |
| 心情 | 确认框 | 照片一起删 | 不可撤销 |

### 5.14 备份与恢复

- 导出：生成一个 `.bloom` 文件，包含全部数据和照片，通过"存储到文件"或"分享到……"保存。
- 导入：只支持"覆盖恢复"。流程：选文件 → 校验 → 预览（导出时间、项目数、记录数、心情数、照片数）→ 确认 → 先自动备份当前数据 → 恢复 → 完成。失败自动回滚，原数据不受影响。
- 备份文件版本比 App 新时拒绝导入，提示先升级 App。
- 超过 30 天未备份（可改为 7/14/30/从不），在"我的"页备份行显示提示，每次打开 App 最多提示一次，不弹窗打扰。

## 6. 信息架构

```
底部页签（5 个）
├─ 今日 ─── 日历 + 选中日期的项目
│           ├─ 历史记录（左上角）
│           ├─ 创建项目（右上角）
│           └─ 项目详情 / 写心情 / 写成绩
├─ 项目 ─── 进行中 / 已暂停 / 已毕业
│           └─ 项目详情 → 编辑 / 项目记录 / 毕业回顾
├─ 统计 ─── 总览 / 月 / 年 → 历史记录
├─ 成就 ─── 成就馆 → 徽章详情
└─ 我的 ─── 心情手账 / 历史记录 / 提醒检查 / 备份与恢复 / 偏好设置 / 关于

全局弹层：毕业典礼、成就弹窗、完美日庆祝、撤销条、确认框、底部面板
```

选 5 个页签而不是 4 个的理由：统计（看自己的数据）和成就（收集徽章）的使用动机不同，合在一个页签里用分段切换会让其中一个被藏起来；5 个页签在 iOS 和 Android 规范内都允许。若后续页签需要增加，优先把"统计"并入"成就"。

## 7. 明确不做

| 不做 | 理由 |
|---|---|
| 账号、登录、云同步 | 纯个人本地使用，不提供服务器 |
| 社交、排行榜、好友监督 | 非目标，且需要服务器 |
| 埋点、远程崩溃上报 | 数据不出手机；用本地诊断日志代替 |
| 广告、内购 | 内部使用 |
| AI 功能 | 不联网，非目标 |
| iPad 适配、横屏 | 仅 iPhone 和安卓手机竖屏 |
| 多语言 | 仅简体中文 |
| 鸿蒙 NEXT（纯血鸿蒙）原生版 | 该系统无法安装 APK，需要单独开发；鸿蒙 4.x 及以下可正常安装 APK |
| 1.0 应用锁、目标奖励、数值型成绩 | 已确认放到后续版本 |
