# Bloom · 方案文档

Bloom 是一个只装在自己手机里的习惯打卡手账，卡通少女风，支持 iOS 和 Android，不联网、不需要账号。每坚持一天，日历上就开一朵小花。

## 关键结论

- **技术**：React Native（Expo 新架构）+ TypeScript；本地 SQLite；SVG 用 react-native-svg 绘制，动画用 Reanimated 直接驱动 SVG 图层；小组件用原生扩展（iOS SwiftUI、Android 组件库）。
- **分发**：iOS 用 TestFlight 内部测试（需要 Apple 付费开发者账号），Android 直接发签名 APK。
- **设计方向**："花园手账"：奶油点阵纸、糖果色块、可可色墨线、小兔吉祥物"朵朵"。签名细节是"每一天都是一朵花"（没打卡是小圆点、部分完成是花苞、全部完成是盛开）。
- **数据安全**：导出/导入 `.bloom` 备份文件（iOS 与 Android 互通）、导入前自动备份、数据库升级前备份、每周本地快照、定期备份提醒。

## 分期

| 期 | 周期 | 目标 | 结束时的状态 |
|---|---|---|---|
| 第 0 期 | 2 周 | 定下长什么样、怎么搭 | 两端能装上，组件和规则引擎可验收 |
| 第 1 期 | 3 周 | 核心打卡闭环 | 内测用户开始每天使用 |
| 第 2 期 | 2.5 周 | 提醒、统计、毕业、备份 | 数据可以备份迁移，提醒可用 |
| 第 3 期 | 3 周 | 成就与心情 | 情绪与奖励体系完整 |
| 第 4 期 | 3.5 周 | 小组件、深色模式与打磨 | 发布 1.0 |

合计约 14 周。按 1 名 React Native 工程师（第 4 期需要会写 SwiftUI 小组件）全职 + 1 名设计师兼职估算，设计比研发提前一期出稿；人员增加可把第 3、4 期部分并行。

## 已确认的决定（2026-11-22）

| 事项 | 结论 |
|---|---|
| 产品名 | 只叫 Bloom，不设中文名 |
| 技术栈 | React Native + Expo |
| 吉祥物 | 小兔"朵朵" |
| Apple 开发者账号 | 将开通，需在第 0 期第 2 周前完成 |
| 深色模式 | 排进 1.0：第 0 期定义深浅两套设计变量，第 4 期实现与走查 |
